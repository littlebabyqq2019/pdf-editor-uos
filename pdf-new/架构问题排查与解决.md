# 架构不匹配问题 - 排查与解决

## 🔴 错误信息
```
standard_init_linux.go:207: exec user process caused "exec format error"
```

## 📋 原因分析

这个错误表明：**Docker镜像的架构与统信系统的CPU架构不匹配**

- 当前构建的镜像：**Linux/AMD64 (x86_64)**
- 统信系统可能是：**Linux/ARM64 (aarch64)** 或其他架构

## 🔍 第一步：确认统信系统架构

在统信电脑上运行以下命令：

```bash
uname -m
```

**可能的结果：**

| 显示结果 | CPU架构 | 是否匹配当前镜像 |
|---------|---------|-----------------|
| `x86_64` | AMD64 | ✅ 匹配 |
| `aarch64` 或 `arm64` | ARM64 | ❌ 不匹配（需重新构建）|
| `armv7l` | ARMv7 | ❌ 不匹配（需重新构建）|

## ✅ 解决方案

### 方案一：重新构建ARM64架构镜像（如果是ARM系统）

如果统信系统显示 `aarch64` 或 `arm64`，需要在Windows电脑上重新构建ARM64镜像。

---

## 🛠️ 构建ARM64镜像（在Windows电脑执行）

### 步骤1：清理现有镜像
```bash
docker rmi pdf-editor:latest
```

### 步骤2：重新构建ARM64镜像
```bash
# 切换到项目目录
cd E:\dev\pdf-new0.2\pdf-new1.3\pdf-new

# 构建ARM64架构镜像
docker build --platform linux/arm64 -t pdf-editor:latest .
```

### 步骤3：导出新镜像
```bash
docker save -o pdf-editor-image-arm64.tar pdf-editor:latest
```

### 步骤4：传输到统信系统
将新生成的 `pdf-editor-image-arm64.tar` 传输到统信系统

### 步骤5：在统信系统上部署
```bash
# 删除旧容器和镜像
docker stop pdf-editor
docker rm pdf-editor
docker rmi pdf-editor:latest

# 加载新镜像
docker load -i pdf-editor-image-arm64.tar

# 运行容器
docker run -d \
  --name pdf-editor \
  -p 5000:5000 \
  -v ~/pdf-editor/processed:/app/processed \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  pdf-editor:latest
```

---

## 🔧 方案二：使用Multi-Platform构建（推荐）

如果不确定架构或需要同时支持多种架构：

### 在Windows电脑上执行：

```bash
# 1. 启用buildx（Docker多平台构建）
docker buildx create --name multiplatform --use
docker buildx inspect --bootstrap

# 2. 构建多架构镜像
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t pdf-editor:latest \
  --load \
  .

# 3. 导出指定架构（根据需要选择）
# 导出AMD64版本
docker save -o pdf-editor-image-amd64.tar pdf-editor:latest

# 或者分别导出
docker buildx build --platform linux/amd64 -t pdf-editor:amd64 --load .
docker buildx build --platform linux/arm64 -t pdf-editor:arm64 --load .
docker save -o pdf-editor-image-amd64.tar pdf-editor:amd64
docker save -o pdf-editor-image-arm64.tar pdf-editor:arm64
```

---

## 🔍 方案三：在统信系统上直接构建（备选）

如果在Windows上构建ARM镜像有困难，可以直接在统信系统上构建：

### 步骤1：传输源代码
将以下文件传输到统信系统：
- Dockerfile
- .dockerignore
- app.py
- file_manager.py
- pdf_processor.py
- image_processor.py
- requirements.txt
- templates/

### 步骤2：在统信系统上构建
```bash
# 安装Docker（如未安装）
sudo apt update
sudo apt install docker.io -y
sudo systemctl start docker
sudo systemctl enable docker

# 构建镜像
cd /path/to/project
docker build -t pdf-editor:latest .

# 运行容器
docker run -d \
  --name pdf-editor \
  -p 5000:5000 \
  -v ~/pdf-editor/processed:/app/processed \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  pdf-editor:latest
```

| 统信系统架构 | 需要的镜像平台 | 构建命令 |
|-------------|---------------|---------|
| x86_64 | linux/amd64 | `docker build --platform linux/amd64` |
| aarch64/arm64 | linux/arm64 | `docker build --platform linux/arm64` |
| armv7l | linux/arm/v7 | `docker build --platform linux/arm/v7` |

## ⚠️ 常见问题

### Q1: Windows上构建ARM镜像很慢？
**A:** 是的，跨架构构建需要QEMU模拟，速度较慢（可能需要30分钟到1小时）。这是正常现象。

### Q2: buildx命令找不到？
**A:** 确保Docker Desktop版本 >= 19.03，并启用实验性功能：
```json
{
  "experimental": true
}
```

### Q3: 如何查看镜像架构？
```bash
docker inspect pdf-editor:latest | grep Architecture
```

## 🚀 快速诊断脚本

在统信系统上运行：

```bash
#!/bin/bash
echo "========================================="
echo "Docker架构诊断"
echo "========================================="
echo ""

echo "1. 系统CPU架构："
uname -m
echo ""

echo "2. Docker版本："
docker version --format '{{.Server.Version}}'
echo ""

echo "3. 镜像架构（如已加载）："
docker inspect pdf-editor:latest 2>/dev/null | grep -A 5 Architecture || echo "镜像未找到"
echo ""

echo "4. 系统信息："
cat /etc/os-release | grep PRETTY_NAME
echo ""

echo "========================================="
echo "如果系统架构不是 x86_64，需要重新构建对应架构的镜像"
echo "========================================="
```

保存为 `check-arch.sh`，然后：
```bash
chmod +x check-arch.sh
./check-arch.sh
```
