## 问题概述

### 现象
文本型PDF经"去红头及公章"处理后：
- ✅ Adobe Reader、Foxit等：公章不可见
- ❌ WPS手机版、WPS电脑版：**公章仍可见**

### 原因
WPS会扫描整个PDF文档中的签名字段对象并渲染其外观流，即使这些对象未被页面引用。

### 解决方案
不仅删除页面引用，还要清空外观流对象并重构签名字段。

## 常见问题

### Q1: 如何知道修复是否成功？

**A:** 运行 `full_test.py`，如果显示：
```
✓ /Annots已设置为null
✓ 未发现任何签名字段对象
```
说明代码层面修复成功。但最终需要用WPS验证。

### Q2: WPS验证时公章仍可见怎么办？

**A:** 按以下步骤诊断：

1. 运行 `check_orphan_objects.py` 检查处理后的文件
2. 查看是否有签名字段对象残留
3. 检查 `/AP` 键是否存在
4. 如果有问题，查看诊断输出并反馈

### Q3: 为什么其他PDF阅读器看不到公章，WPS能看到？

**A:** 
- 标准PDF阅读器：只渲染页面 `/Annots` 中引用的注释
- WPS：会扫描全文档，渲染所有包含 `/AP` 的签名字段

这是WPS的特殊行为，需要特殊处理。

### Q4: 修复后的PDF是否兼容？

**A:** 是的。修复后的PDF：
- 在所有PDF阅读器中都能正常打开
- 文本、图像、格式都保持不变
- 只是删除了公章的显示

### Q5: 如何处理批量文件？

**A:** 
1. 使用Web界面上传多个文件
2. 点击"去红头及公章"
3. 系统会自动处理所有文件并打包成ZIP

### Q6: 日志显示什么？

**A:** 关键日志：
```
[DEBUG] 发现中下部的签名字段/公章，开始彻底删除
[DEBUG] 发现/AP/N引用 xref=71
[DEBUG] 已清空外观流对象 xref=71
[DEBUG] 重构签名字段对象 xref=72
[DEBUG] 已重构 xref=72，移除了/AP、/V、/DR键
[DEBUG] 已将/Annots设置为null
[DEBUG] 方法零成功删除注释形式的公章
```
