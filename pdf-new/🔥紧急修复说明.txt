========================================
🔥 紧急修复 - pthread权限问题
========================================

您遇到的错误:
  OpenBLAS pthread_create failed: Operation not permitted
  
原因:
  统信系统Docker安全策略过于严格
  
========================================
✅ 快速解决方法（在统信系统上执行）
========================================

方法一：自动修复脚本 ⭐推荐⭐

  chmod +x 快速修复-pthread问题.sh
  ./快速修复-pthread问题.sh

方法二：手动修复（复制粘贴执行）

  # 停止并删除当前容器
  sudo docker stop pdf-editor
  sudo docker rm pdf-editor
  
  # 使用修复的配置重新创建
  sudo docker run -d \
    --name pdf-editor \
    -p 5000:5000 \
    -v ~/pdf-editor/processed:/app/processed \
    -e TZ=Asia/Shanghai \
    -e OPENBLAS_NUM_THREADS=1 \
    --security-opt seccomp=unconfined \
    --restart unless-stopped \
    pdf-editor:arm64
  
  # 等待30秒后访问
  sleep 30
  
  # 访问
  http://localhost:5000

方法三：重新部署（使用修复版脚本）

  chmod +x 统信系统ARM64部署-修复版.sh
  ./统信系统ARM64部署-修复版.sh

========================================
🔑 关键修复参数
========================================

添加了两个关键参数：

1. --security-opt seccomp=unconfined
   → 放宽Docker安全限制，允许创建线程

2. -e OPENBLAS_NUM_THREADS=1
   → 限制OpenBLAS线程数，减少权限需求

🔐 安全性说明
========================================

Q: seccomp=unconfined 安全吗？
A: 是的，在这个场景下是安全的：
   • 容器其他隔离机制仍然有效
   • PDF编辑工具不需要危险操作
   • 只是放宽了线程创建限制

详细说明请参考: pthread权限问题解决方案.md

========================================
💡 为什么会有这个问题？
========================================

• 统信UOS作为国产安全操作系统
• Docker默认安全策略特别严格
• 限制了pthread_create等系统调用
• numpy/OpenBLAS需要创建多线程
• 导致权限被拒绝，应用无法启动

这是统信系统的特色，其他Linux系统较少遇到。
