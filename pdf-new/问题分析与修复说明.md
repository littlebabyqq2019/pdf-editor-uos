# PDF公章去除不彻底问题分析与修复

## 问题描述

对于文本型PDF文件，点击"去红头及公章"按钮后：
- ✅ 在大多数PDF阅读软件中，红头和公章都看不见
- ❌ 在WPS手机版和WPS电脑版中，红头看不见，但**公章仍然可见**

## 问题根因分析

### 1. 问题现象

通过深度分析处理前后的PDF文件结构，发现：

**原始文件（第2页）：**
```
/Annots [ 72 0 R ]  <- 页面包含一个注释引用

注释对象 xref=72:
<<
  /FT /Sig                   <- 签名字段
  /Subtype /Widget           <- 表单控件
  /AP <<                     <- 外观流（Appearance Stream）
    /N 71 0 R                <- 指向外观对象
  >>
  /Rect [ 343.87 192.23 466.93 315.29 ]  <- 位置（第2页中下部）
>>
```

**处理后的文件（第2页）：**
```
/Annots null  <- /Annots引用已被删除

但是！签名字段对象 xref=69 仍然存在：
<<
  /FT /Sig
  /Subtype /Widget
  /AP <<                     <- 外观流仍然存在！
    /N 68 0 R
  >>
  /Rect [ 343.87 192.23 466.93 315.29 ]
>>
```

### 2. 核心问题

**旧代码只删除了页面的`/Annots`引用，但没有清除签名字段对象的外观流（`/AP`键）。**

- **大多数PDF阅读器**：只渲染页面`/Annots`中引用的注释，因此看不到公章
- **WPS**：会扫描整个PDF文件，渲染所有包含`/AP`外观流的签名字段对象，即使它们没有被页面引用

这就是为什么WPS仍然能显示公章的原因。

## 修复方案

### 修改位置

文件：`pdf_processor.py`
方法：`_remove_annots_from_page_object()`

### 修复内容

在删除`/Annots`引用之前，对每个中下部的签名字段对象执行以下操作：

#### 步骤1：清空外观流对象
```python
# 提取/AP/N引用的外观流对象xref
ap_match = re.search(r'/AP\s*<<\s*/N\s+(\d+)\s+0\s+R', annot_obj)
if ap_match:
    ap_xref = int(ap_match.group(1))
    # 将外观流对象替换为空流
    empty_obj = "<< /Length 0 >>\nstream\n\nendstream"
    doc.update_object(ap_xref, empty_obj)
```

#### 步骤2：重构签名字段对象，移除/AP、/V、/DR键
```python
# 构建新对象：只保留必要的键
new_obj = """<<
  /T (签名字段名)
  /F 132
  /Rect [ x0 y0 x1 y1 ]
  /P page_xref
>>"""
doc.update_object(xref, new_obj)
```

#### 步骤3：删除页面的/Annots键
```python
doc.xref_set_key(page_xref, "Annots", "null")
```

#### 步骤4：垃圾回收清理
```python
doc.save(output_path, garbage=4, deflate=True, clean=True)
```

## 关键技术点

1. **PDF签名字段结构**
   - `/FT /Sig`：字段类型为签名
   - `/Subtype /Widget`：表单控件
   - `/AP`：外观流，定义如何显示
   - `/V`：签名值
   - `/DR`：默认资源

2. **PDF渲染差异**
   - 标准PDF阅读器：只渲染页面引用的注释
   - WPS：扫描全文档，渲染所有外观流

3. **彻底删除方法**
   - 清空外观流对象内容
   - 重构签名字段对象，移除关键键
   - 删除页面引用
   - 垃圾回收清理未引用对象
